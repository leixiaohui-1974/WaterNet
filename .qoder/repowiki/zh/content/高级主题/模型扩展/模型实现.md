## BaseLumpedModel 状态管理与数值保护机制

`BaseLumpedModel` 是所有集总参数降阶模型的抽象基类，为子类提供统一的仿真框架、状态管理和数值稳定性保护。

### 状态管理
基类通过实例变量管理模型的动态状态，包括：
- `current_V`: 当前蓄水量（m³）
- `current_H`: 当前水位（m）
- `current_Q_out`: 当前出流量（m³/s）
- `time`: 当前仿真时间（s）
- `history`: 存储历史状态的字典，用于结果分析和可视化

状态的更新由 `_update_physical_states()` 方法协调，该方法根据平均入流和出流，结合连续性方程 `dV/dt = Q_in - Q_out` 更新蓄水量，并通过 `V_to_H_func` 函数计算新水位。此方法支持两种模式：传统的 `V = f(H)` 关系和更精确的 `V = f(Q, H)` Q-H耦合模式。

### 物理关系函数调用
模型通过注入的可调用对象（`V_to_H_func`, `H_to_Q_func`, `QH_to_V_func`）实现与具体物理关系的解耦。这些函数在初始化时传入，允许模型适应不同的几何和水力特性。基类在调用这些函数时，通过 `_safe_V_to_H()` 和 `_safe_H_to_Q()` 等安全包装器进行保护，防止因函数返回非有限值或负出流而导致仿真崩溃。

### 数值保护机制
为了确保仿真过程的数值稳定性，基类实现了多层保护：
1.  **参数验证**：在 `__init__` 中严格检查 `dt`（正值）和 `initial_V`（非负值）。
2.  **范围限制**：使用 `np.clip()` 将计算出的蓄水量限制在 `min_volume` 和 `max_volume` 之间，防止溢出。
3.  **安全转换**：物理关系函数的调用被包裹在异常处理中，若计算失败，会发出警告并返回当前状态或默认值，而非中断仿真。
4.  **残差保护**：在 `step()` 方法中，对计算出的出流量进行 `max(0.0, Q_out)` 操作，确保其非负。
5.  **历史记录限制**：`_record_state()` 方法限制历史数据的最大长度，防止内存耗尽。

## HydroModel 接口契约与变量命名规范

`HydroModel` 是为紧耦合求解场景设计的抽象基类，其核心在于通过残差方程与求解器交互。

### 方法契约
`get_equations()` 和 `get_variable_names()` 之间存在严格的契约关系：
- **数量匹配**：`get_variable_names()` 返回的变量数量必须与 `get_equations()` 返回的方程数量完全相等。求解器将根据此关系建立方程组。
- **逻辑对应**：每个变量都应有至少一个方程来描述其行为。例如，一个流量变量 `Q_pipe` 通常由一个连续性方程控制。
- **接口验证**：`validate_interface()` 方法会自动检查这两个方法的返回值是否满足契约，是开发和调试的重要工具。

### 变量命名规范
清晰、一致的命名规范对于构建大型、复杂的水力系统至关重要。推荐的命名约定如下：
- **节点水位**：`H_节点名`，例如 `H_ReservoirA`。
- **管段流量**：`Q_管段名`，例如 `Q_Channel1`。
- **内部变量**：`H_模型名_internal_索引` 或 `Q_模型名_seg_索引`，用于表示模型内部的虚拟节点或分段，例如 `H_Channel1_internal_0`。
- **其他变量**：根据物理含义命名，如 `V_蓄水池` 表示蓄水量。

这种命名方式确保了在整个系统中变量名的唯一性，并能清晰地表达变量的物理意义和所属模型。

## 自定义模型实现示例

### 实现简单线性关系模型
以下示例展示如何继承 `HydroModel` 实现一个简单的线性关系模型，该模型描述出流量与上游水位的线性关系 `Q_out = k * H_up + b`。

```python
class LinearFlowModel(HydroModel):
    def __init__(self, name: str, upstream_node: str, k: float = 1.0, b: float = 0.0):
        super().__init__(name, [upstream_node])
        self.upstream_node = upstream_node
        self.k = k
        self.b = b

    def get_variable_names(self) -> List[str]:
        # 引入一个流量变量
        return [f'Q_{self.name}']

    def get_equations(self, variables: Dict[str, float], dt: float, 
                     prev_states: Dict[str, float]) -> Dict[str, float]:
        # 获取上游水位和当前流量变量的值
        H_up = variables.get(f'H_{self.upstream_node}', 0.0)
        Q_out = variables.get(f'Q_{self.name}', 0.0)
        
        # 定义方程：Q_out - (k * H_up + b) = 0
        residual = Q_out - (self.k * H_up + self.b)
        
        return {f'linear_flow_eq_{self.name}': residual}
```

### 实现复杂非线性系统
对于更复杂的系统，如基于传递函数的IDZ模型，继承 `BaseLumpedModel` 更为合适。子类必须实现 `step()` 方法，该方法负责执行一个时间步长的完整计算逻辑。

```python
class CustomIDZModel(BaseLumpedModel):
    def __init__(self, dt: float, initial_V: float, V_to_H_func, H_to_Q_func, 
                 tau: float, T_delay: float, alpha: float, name: str = "CustomIDZ"):
        super().__init__(dt, initial_V, V_to_H_func, H_to_Q_func, name)
        self.tau = tau
        self.T_delay = T_delay
        self.alpha = alpha
        self.delay_steps = int(np.ceil(T_delay / dt))
        self.delay_buffer = [0.0] * self.delay_steps
        self._compute_coefficients()

    def _compute_coefficients(self):
        # 计算离散化系数
        self.a1 = np.exp(-self.dt / self.alpha)
        self.b0 = (1 - self.a1)
        self.c0 = 1.0 + self.tau / self.dt
        self.c1 = -self.tau / self.dt

    def step(self, Q_in: float) -> Dict[str, float]:
        # 1. 延迟处理
        delayed_input = self.delay_buffer[0]
        self.delay_buffer = self.delay_buffer[1:] + [Q_in]

        # 2. 一阶滤波器计算 (模拟传递函数)
        u_filtered = self.c0 * delayed_input + self.c1 * getattr(self, 'prev_u', 0.0)
        Q_out = self.a1 * getattr(self, 'prev_y', 0.0) + self.b0 * u_filtered

        # 3. 更新内部状态
        self.prev_y = Q_out
        self.prev_u = delayed_input

        # 4. 更新物理状态
        Q_in_avg = (Q_in + getattr(self, 'prev_Q_in', 0.0)) / 2.0
        Q_out_avg = (Q_out + self.current_Q_out) / 2.0
        self._update_physical_states(Q_in_avg, Q_out_avg)
        self.current_Q_out = Q_out

        # 5. 记录状态
        self._record_state(Q_in)

        # 6. 返回结果
        return {
            'Q_out': Q_out,
            'H_out': self.current_H,
            'V': self.current_V,
            'time': self.time
        }
```

## 边界条件与初始状态验证

### 边界条件处理
边界条件通过模型的输入参数和连接方式来体现。
- **独立模型**（`BaseLumpedModel`）：边界条件是时间序列的入流 `Q_in`，在 `step()` 方法中作为参数传入。
- **耦合模型**（`HydroModel`）：边界条件是系统中其他模型提供的变量值。例如，一个渠道模型的上游水位可能由上游水库模型的出水位决定。这些值通过 `variables` 字典传入 `get_equations()` 方法。

### 初始状态验证
正确的初始状态是仿真稳定和物理合理的前提。基类和子类都应进行验证：
- **基类验证**：`BaseLumpedModel.__init__` 调用 `_validate_initial_state()`，测试 `V_to_H_func` 和 `H_to_Q_func` 在 `initial_V` 处是否返回有限值。
- **子类验证**：子类应在 `__init__` 中验证自身参数的合理性（如 `MuskingumModel` 验证 `K > 0` 且 `0 <= x <= 0.5`）。
- **物理一致性**：确保初始蓄水量 `initial_V` 对应的水位和出流在物理上是合理的。例如，不应出现负的出流量。
- **接口验证**：对于 `HydroModel`，应使用 `validate_interface()` 方法检查 `get_variable_names()` 和 `get_equations()` 的实现是否匹配。

## 结论
通过继承 `BaseLumpedModel` 或 `HydroModel`，开发者可以灵活地创建各种复杂度的水力模型。`BaseLumpedModel` 提供了强大的状态管理和数值保护，适用于独立运行的降阶模型；而 `HydroModel` 则通过残差方程接口，为构建大规模、多模型耦合的复杂系统提供了坚实的基础。遵循文档中阐述的设计原则、契约关系和验证方法，能够确保所创建模型的健壮性、准确性和可维护性。
